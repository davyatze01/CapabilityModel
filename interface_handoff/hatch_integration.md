# Capability-grid hatch overlay — integration instructions

This package adds the diagonal hatch pattern for the capability grid to the
web map. It replaces whatever hatch/pattern fill your qgis2web export
produced for that layer — qgis2web can't translate that symbol type
correctly, so this is a small pre-rendered image layer wired in by hand
instead.

## What you received

Everything below arrives zipped as one file, `hatch_handoff.zip`
(auto-generated by the pipeline at `outputs/gpkg/<slug>/hatch_handoff.zip` —
regenerated fresh on every run, so always grab the latest one). Unzip it;
you should have these 6 files, all at the top level (no subfolders):

```
care.png
nutrition.png
restorativeness.png
manifest.js
legend.png
hatch_grid_static.js
```

- **`care.png` / `nutrition.png` / `restorativeness.png`** — the hatch
  pattern, one image per capability, already positioned on the real map
  coordinates (EPSG:4326, same as the rest of your export).
- **`manifest.js`** — tells the code where each image sits on the map, as a
  `<script>` global (`window.HATCH_MANIFEST`). It's a `.js` file rather than
  plain JSON because browsers block loading local JSON files with `fetch()`
  over `file://` — if your page runs from disk rather than a server (like
  the rest of this interface), this is the only format that works.
- **`legend.png`** — the 5-class legend (Very Low → Very High), already
  labeled, as one image. Use it in place of whatever legend qgis2web
  generated for the old hatch layer.
- **`hatch_grid_static.js`** — the code that loads the images as map layers
  and lets you switch between capabilities.

## Where to put the files

```
resources/hatch/care.png
resources/hatch/nutrition.png
resources/hatch/restorativeness.png
resources/hatch/manifest.js
resources/hatch/legend.png
resources/hatch_grid_static.js       <- this one only, one level up from the rest
```

(If your project uses different folder names, that's fine — just keep the
5 hatch files together in one folder, since the code assumes `manifest.js`
sits next to the PNGs.)

## Steps

1. Unzip `hatch_handoff.zip` and sort the 6 files into place as above.

2. In your HTML page, add these two lines — **before** any script that
   creates map layers, and in this order:

   ```html
   <script src="resources/hatch/manifest.js"></script>
   <script src="resources/hatch_grid_static.js"></script>
   ```

3. Once your map object exists, load and add the layers:

   ```js
   window.makeHatchGridImageLayers('', 'resources/hatch/')
       .then(function (hatchLayers) {
           // hatchLayers = { care: ..., nutrition: ..., restorativeness: ... }
           Object.keys(hatchLayers).forEach(function (cap) {
               map.addLayer(hatchLayers[cap]);
           });
           window.__hatchLayers = hatchLayers;
           window.setHatchCapability(hatchLayers, 'care'); // whichever starts active
       });
   ```

   (The first argument is left blank because `manifest.js` from step 2
   already provides the data — that argument only matters as a fallback URL
   if you ever load this without the script tag.)

4. Wherever your interface currently switches which capability is shown
   (a dropdown, buttons, etc.), call:

   ```js
   window.setHatchCapability(window.__hatchLayers, theSelectedCapability);
   ```

   `theSelectedCapability` must be one of `'care'`, `'nutrition'`,
   `'restorativeness'`.

5. **Important — hide the old hatch layer from your qgis2web export.** Find
   the vector layer your export generated for the capability grid (it'll be
   named something like `capability_grid` or `zz_capability_grid` in your
   layers file, and its title/legend usually mentions "capability grid" or
   the class labels Very Low/Low/Medium/High/Very High). It will render as a
   garbled or broken hatch — that's expected, it's the exact problem this
   package works around. Set it to not visible by default, e.g. find its
   `lyr_XXX.setVisible(true)` call and change to `false` (or remove it from
   your layer list entirely if you don't need it for anything else).

6. This package only replaces the hatch. Everything else in your export
   (colored service layers, hexagon outline, basemap, etc.) is unrelated and
   unaffected — leave those as they are.

## Checking it worked

Open your page and confirm:
- The hatch pattern shows up over the study area, in the right place.
- Switching capability (step 4) changes which hatch is shown.
- Zooming in/out is completely stable — no flickering, no lines
  appearing/disappearing, no shift in position. (If you see any of that,
  you're probably still seeing the old broken layer from step 5 underneath —
  double check it's hidden.)
- The hatch still looks correct when combined with your colored layers
  underneath — it's semi-transparent by design, so colors should show
  through both the white background and the black lines.

## If you regenerate your qgis2web export later

Re-exporting will likely regenerate your HTML/layers files from scratch and
undo steps 2-5 above (this hatch overlay isn't part of that export — it's
never going to be, since qgis2web can't produce it correctly). After any
future re-export, just redo steps 2-5 once more with the same files.
